# 4. Preregistration work

A preregistration is the plan written down and tagged before the first confirmatory run. It is what lets a failed prediction count as a finding. Fill the skeleton in section 4 by Nov 4; freeze it Nov 5 (see 05).

## 1. What it must contain
1. One question, one sentence, stylised-setting wording (no real-world claim).
2. Environment rules, prompts, model list with exact versions, temperature, rounds, swarm sizes.
3. Arms: main, positive control, negative/sham control, mechanism arm.
4. **Primary outcome** with its exact formula, defined on the actor of interest, and its parts reported separately.
5. **Written predictions** with direction and size, before data. Include at least one you expect to fail.
6. **Equivalence margin** for any "matches / no difference" claim, and the rule for a null (below).
7. Sample sizes, seeds (and which seeds are discovery vs confirmation), power or minimum detectable effect.
8. Gate and fallback rule.
9. Analysis code, committed, run on synthetic data before freezing.
10. Evidence labels used in the report: **preregistered / fixed before outcomes / exploratory**.
11. Deviations log format (dated, what, why, "touched no prompt, margin or threshold: yes/no").

## 2. Rules for reading results
- A null is read only against the stated margin; report the largest effect the interval allows.
- Check for determinism before trusting a narrow interval (identical runs make tiny intervals meaningless; count identical paths).
- Positive control must pass first; if it fails, nothing else is interpreted.
- Failed predictions go in the abstract.

## 3. Timing rule for this sprint
Timing and plumbing runs before Nov 6 use throwaway seeds and record no outcome analysis. Confirmatory seeds are generated by a fixed rule written in the plan (for example seeds 101-110) and are not run before the freeze.

## 6. Fixes from the audit (added 2026-11-02; all required before the freeze)
1. **A margin per question.** Fill one "matches / no effect" margin for each of Q1-Q7 in the skeleton, fixed before data.
2. **Holm correction** inside each lens (Sandboxes, Agent Networks, Oversight); report raw and adjusted p-values (see 13, section 1).
3. **Manipulation checks.** Log every arm's prompt and run an automatic test, before any data, that the board is mentioned or hidden exactly as the arm intends (a "blind" arm that fails this is not blind).
4. **Independent runs.** Each seed changes the world layout, bot order and starting pool; no two episodes share a path.
5. **Positive control every batch.** Re-run the scripted board-user in each batch; log pass or fail; a failing batch is discarded and rerun only after a logged fix.
6. **Prompt rule.** Templates P-MAIN, P-OPEN, P-FOCUS (and optional P-MIN) are frozen with a hash; chosen from plumbing tests, never from outcomes (see 13, section 2).
7. **Sample sizes.** At least 20 episodes per hosted cell and 10 per local cell; compute the minimum detectable effect from pilot spread.
8. **Reply cache.** Cache every request and reply (hashed); reruns replay from the cache (the API has no seed).
9. **Reasoning tokens.** Record them; set `max_output_tokens` high enough to avoid empty replies; log truncations and report the empty-reply rate.
10. **Numbers file and rebuild.** `numbers.md` maps every figure to a script and a data key; a one-command rebuild from a clean clone.
11. **Model choice by rule.** Local models by the selection rule, hosted roster by priority and a plumbing check (see 13, sections 4 and 6).
12. **Log everything** as specified in 13, section 3.
13. **Every arm and ablation is listed in the freeze.** Anything added later is labelled exploratory.
